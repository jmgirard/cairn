# Lessons

Durable repo lessons — build quirks, testing tricks, gotchas worth
remembering next time — captured at milestone end and surfaced at plan time.
Not status, not decisions: a lesson is a reusable "how this repo actually
behaves" note. Cross-cutting *choices* still go to `DECISIONS.md`.

One line per lesson: `- YYYY-MM-DD (M<NN>): <lesson>`. One cap
(tracking-rules weight-caps): 50 lines, met by retiring or pruning entries.
Current knowledge: a lesson proven false is corrected in place (D-045).
Lessons also *leave*: one retires when a test fails on the mistake it warns
about, when another file's slot owns its content, or when a matured family
graduates whole into a doctrine module; pruning the stalest is the last resort
rather than the first (D-051, D-055).

- 2026-07-16 (M56+M65, consolidated M78/M83): "green" is only as wide as what you ran. Bash's working directory persists across tool calls and piping a verify through `| tail -1` makes the chain exit-blind (`tail` exits 0 even when `discover` ImportErrors) — a lingering `cd cairn` silently skipped all three suites, and at the M65 gate the pipe hid a red exit. Run suites from the repo root, check each exit code explicitly, and never chain a commit/push/marker write after a piped run. And `cairn_validate` green is NOT the suites green: a `cairn/references/` edit passing every validate check can still break a `skills/tests` guard, and a trivial-tier docs commit pushed main red because only validate was run — any references or template edit runs the three suites too, trivial tier or not. **Extended M121:** the same blindness has a SEARCH form, and both halves shipped. `grep eleven skills/` was offered as evidence that a finding in `cairn/DECISIONS.md` was closed — an empty result from the wrong tree reads exactly like an empty result from the right one, so scope a verification command to the tree that holds the claim. And `git grep <rev> -- 'skills/shared/*.md'` is a PATHSPEC, not a shell glob: git's wildmatch lets `*` cross `/`, so it also matches `profiles/` and `templates/` (79 hits became 119) — while UNQUOTED the shell expands it first, silently binding the corpus to the working tree instead of the revision named in the command. Write pathspec paths out rather than globbing them.
- 2026-07-16 (M60): refines M19 — hook *registrations* (hooks.json) snapshot at process start, but each script BODY is re-read per invocation from the symlinked checkout: editing an already-registered hook goes live mid-session (the new merge_guard renamed the marker during M60's own merge), while a newly-registered hook stays dead until a fresh conversation; a fixture test still proves only what a hook prints, and live-fire plans must split the two cases.
- 2026-07-18 (M71, corrected M75, consolidated M92): hooks trap on MATCHING and on SHIPPING. Matching: a `matcher` made only of `[a-zA-Z0-9_|]` (or `[a-zA-Z0-9_|, -]`) takes a LITERAL path — split on `|`/`,`, each alternative exact-matched — so `|` does NOT buy regex treatment; only a metacharacter (`mcp__.*__spawn_task`) reaches `new RegExp`, and that path is unanchored, so keep the hook's own tool-name regex the same suffix shape (full dispatch: `references/claude-code-hooks.md`). Shipping: a new hook touches four places beyond the script itself — `hooks.json`, BOTH `TestNonCairnNoOp` payload collections in `hooks/tests/test_hooks.py` (dict + garbage-stdin tuple), `cairn/DESIGN.md`'s inventory bullet (count words included), and `test_positioning_guard.py`'s hardcoded `HOOKS` tuple, NOT derived from `hooks/`.
- 2026-07-18 (M72, extends M33, trimmed M92/M98): the merge guard is direction-blind — `git merge main` INTO a feature branch is denied though tracking-rules prescribes merging when main moves, so sync a feature branch with `git rebase main` instead.
- 2026-07-18 (M73): `gh pr create`/`ready`/`merge` all use GraphQL, whose quota can be exhausted while REST is healthy — `gh api repos/{owner}/{repo}/pulls --input <json>` opens a PR (draft included) when `gh pr create` is rate-limited. Never route the MERGE through REST to dodge a limit: merge_guard is a PreToolUse hook matching the merge commands, so a REST merge silently bypasses the approval marker — the enforcement boundary M72 documented.
- 2026-07-18 (M81/M91, trimmed M98): re-dating a DERIVED references page restarts its 180-day staleness clock though half its inputs were never re-read — age a synthesis note from its OLDEST un-re-read input (F4/88).
- 2026-07-19 (M90): `Edit` with `replace_all` applies ONE fixed indentation to every match — in Python that silently changes block structure and stays valid. A nested loop dedented to its parent's level ran once after the parent finished, against the last-bound variable, so a two-surface guard checked one surface and passed green (F1/96). Never `replace_all` a line whose correct indentation differs between occurrences; prove a guard reddens for EACH input it covers.
- 2026-07-20 (M99): a figure stated INSIDE the artifact it measures is a fixed point — writing it changes it. The milestone template's budget block stated its own preamble length and drifted twice in one authoring session under full attention; the fix was not a better guard but DELETING the figure, since the claim worth pinning was that the budgets fit, which a guard asserts against a measured value. Prefer a tool that prints the number over prose that states it. Second instance (M115): a review section stated `cairn_validate`'s advisory COUNT, and the commit writing it made the number wrong — the milestone file is inside the corpus the advisory scans, so the count went 8 -> 9 -> 10 as each correction was written. Third instance (M118), where the remedy differs: a committed ledger measuring EVERY milestone's peak size necessarily includes the measuring milestone, and M118's own growth moved two of its own cells mid-review (its peak 149 -> 151, the over-6,000 work-log count 5 -> 6). Deletion was not available — the numbers were the deliverable — so the fix is to pin every count to a named measurement commit and mark it a dated observation, never a standing fact.
- 2026-07-20 (M99): rewriting an instruction from "transform X into Y" to "author a fresh Y" silently drops X's disposal — step 9 said "compress the milestone file and move it", where the move deleted the live copy implicitly; authoring from a template made the summary a NEW file and nothing removed the old one, orphaning it until `cairn_validate` caught it (F4/85). When a rewrite changes what an artifact IS, re-derive every side effect the old phrasing carried implicitly.
- 2026-07-20 (M95, consolidated M105/M118): the mutation harness catches an anchor whose prose REFLOWED, but nothing catches an anchor authored against text that was never read out — three asserts in a new guard failed at once on wrap points invented from the draft, and a `[:34]` slice hack nearly pinned a truncated clause. Author anchors by copying the target file's actual bytes, never from the text you just wrote. When the phrase you need already wraps, the remedies rank: re-wrap the TARGET so the sentence sits on one physical line (M118, a template preamble sentence — it also keeps the anchor registrable in the mutation harness, which a wrapped one is not); failing that, span the wrap with a `\s+` matcher (`at phase\s+end`), never a `.`-based or literal `assertRegex`, since `.` cannot cross a newline; and keep any `assertIn` anchor on a phrase that does sit on one line.
- 2026-07-20 (M95): an inversion sweep's probe locators must be drawn from the GUARD files, not from the prose being cut — a locator that misses reads exactly like a rule that is unguarded, and two rules were reported unpinned on phrases (the elaboration, not the rule) that no guard had ever asserted. Confirm a "GREEN/unpinned" verdict by grepping the guards for what they actually pin before believing it. **Extended M123:** the locators can be right and the SCOPE still wrong — every §8 assert read the whole FILE while every criterion it serves is scoped to the section, so six acceptance-criterion clauses could be moved verbatim out of §8 into §7 with all 777 tests green and no anchor text touched. An anchor proves the phrase exists SOMEWHERE in what you handed it; scope the read to the unit the criterion names, and test the slice at BOTH bounds (a §9 appended after §8 catches an upper bound that runs to EOF).
- 2026-07-20 (M100): the mutation engine redirects `pathlib.Path.read_text` ONLY — a prose-guard reading its target via `open()` is invisible to the blanking, so EVERY one of its registrations reports not-reddening at once; author guard files with `Path.read_text`, and read an all-entries-fail harness result as "the engine can't see this guard", not as N bad anchors.
- 2026-07-20 (M100): an enforcement check must fail LOUD, never open — review found four paths where the binding-criteria check silently bound nothing (HTML comments counted in the scanned corpus, a present-but-unparseable section skipped, an id-prefix marker match, a malformed slot skipped). Silence must mean "nothing binds", never "binding content the parser missed": a present-but-unparseable input is a finding, not a skip, and id tokens in matchers get word bounds.
- 2026-07-20 (M101): a cairn/references/ page committed outside a milestone (RR ingest, docs commit) reds the scripts suite until its state is pinned in TestShippedPageStateLedger — the ledger is a characterization test over the real tree, so the pin plus its one-line justification land in the same commit as the page (526aba6 left main red until M101's branch).
- 2026-07-20 (M104): editing guarded skill-prose can redden a DIFFERENT guard — broadening one clause reflowed an ADJACENT guard's asserted phrase ("is not re-reported under the Staleness bullet") across a line break, and the failing test named a rule I had not touched (M23 recurrence). After any skill-prose edit, grep that EVERY nearby guard's asserted substring is still contiguous on one physical line, not only that your new anchor is.
- 2026-07-20 (M104): a rule generalized to "every X" can silently override a scoped sibling that already handles a subclass of X differently — a work-only staleness bullet applied to "every in-progress milestone" collided with `check_release_window`'s deliberate any-entry leniency for release-shaped ones (D-017); the blame-history lens caught the regression the diff-bug lens read past. When broadening a scope word, check every existing mechanism that treats a subclass differently.
- 2026-07-20 (M105): `gh pr merge` squashes the REMOTE branch as GitHub sees it, not your local HEAD — review-phase commits made AFTER the review-start `git push` (AC ticks, the Review section, the fan-out record) are silently dropped from the squash unless re-pushed. M105's deliverable survived only because the code landed in the pre-review push; the milestone-file bookkeeping did not (the archive summary caught it, but main's squash lacks it). Re-push the branch right before writing `.merge-approved`.
- 2026-07-23 (M109): a `unittest` skip can't be asserted directly — `skipTest` raises, it doesn't return — so a machine-coupled live test whose skip path must be proven on any machine factors the skip decision into a helper that raises `SkipTest`, then a second test does `assertRaises(SkipTest)` against a synthetic empty input. And to prove a resource-backed test hit a fixture and never the real store, spy on the reader (`read_records`) and assert the captured path is the fixture — an exit-code-only assertion passes just as happily against the real store.
- 2026-07-20 (M102): the verify suites' wall time was process spawns, not test count — a script CLI exposing a callable seam (`cairn_validate.main(argv)` / `run(root)` returning report + exit code) runs in-process from tests (route the shared `run()` helper through it), cutting `scripts/tests` ~20s→6.2s while a few retained `_spawn` tests keep the argv/exit-code/`die_not_cairn` boundary; a hook test must keep invoking the hook as a real subprocess (M07) but its git-init/config/add/commit `setUp` becomes `shutil.copytree` of a once-built template repo (360 git spawns→~0, hooks ~15s→9s). Separately: a test globbing live `cairn/milestones/M*.md` reds whenever no milestone is in flight — copy the canonical template into a temp milestone path and parse that for a state-independent shape guarantee.
- 2026-07-23 (M111): post-merge hygiene archives a milestone by ADDING a `done` row, which can push the ROADMAP over the 5-row terminal-row retention cap — prune the oldest `done` row (it survives in `archive/` + git) in the SAME archive commit, not as a later fix. And never `;`-chain `cairn_validate ; git commit ; git push`: `;` runs the commit even when validate FAILs, pushing main red (I did, then fixed forward) — run validate as its own step and `&&`-gate the commit, or check its exit explicitly (extends M56).
- 2026-07-24 (M112): a milestone that changes doctrine *wording* has more surfaces than the skills it edits — README, templates, and other user-facing docs restate the same doctrine and go stale silently. Scope the AC to the whole surface (grep the repo for the OLD phrasing), not just the skill files; M112 scoped AC1 to "the three skill files" and shipped a README/doctrine contradiction only the blame-history reviewer caught at the gate.
- 2026-07-25 (M113): a second bounding pass with its own floor silently undoes the first pass's floor. A block-level bound with a 3-entry floor, backstopped by a line-level bound with a 1-line floor, went NON-MONOTONIC in the budget — at budget 100-304 a work log showed zero entries and reported "newest 1 of 42 lines shown", the shown line being blank, while budget 0 showed three entries. Two floors on one quantity is the smell; bound the thing that is actually unbounded (there, the prose above the first entry) instead of adding a pass over everything.
- 2026-07-25 (M113, inverts M104): adding prose can give an EXISTING guard false coverage, not just redden it. A new rulebook row naming `work-log format` made that label occur twice, so `test_stated_advisory_label_matches_the_emitted_label`'s bare-label `assertIn` would have passed with the advisory's rule deleted outright — the mutation harness caught it ("block locator must occur exactly once"). - 2026-07-25 (M113, trimmed M122): a hook needing a rule the scripts already implement must reuse THEIR normalization, not re-derive it — the two layers cannot share code (hooks import only `cairn_common`), so their agreement is matched BY HAND and is a review item, never an assumption. The heading instance is retired: `TestHeadingNormalizationContract` (M122) now fails when the two diverge on case, whitespace, the `## ` prefix or fences, so what is still carried here is only the rule for the NEXT behaviour the two layers have to share.
- 2026-07-26 (M115): `check_dangling_ids` SKIPS tokens numerically above the max assigned id (forward prose, D-023's false-positive tolerance) — so appending one D-entry raises the ceiling and unmasks every previously-invisible dangling reference below it at once. Three appeared the moment D-067 landed. A clean `dangling id tokens` line is therefore not evidence that no dangler exists, only that none sits below the current max; expect a batch when the next entry is appended.
- 2026-07-26 (M115): a citation to an artifact living on ANOTHER milestone's unmerged branch (an RR under `reviews/archive/`, a D-entry) resolves to nothing on main and ships as a pointer to a missing file. Convention, verified: only RR01 and RR04 are cited in non-test prose under `skills/`, both archived on main. - 2026-07-27 (M114): work-log entries state decision-relevant facts, never characterizations — adjectives and superlatives ("terser", "narrower", "the longest") are falsifiable surface a certification round reds on. M114's late rounds found four such conclusions false while every measured number beside them reproduced exactly; the numbers were never the problem, the rhetoric drawn from them was.
- 2026-07-27 (M116): a D-entry sentence saying what a guard COVERS states a mechanical fact the author has almost never re-run at the moment of writing, and no suite can contradict it — D-071 claimed a guard "reds on any edit" to an entry it pins five spans of, then D-072 dropped one of the five while correcting exactly that, both green under all three suites and `cairn_validate`; a fresh-context reader caught each. Re-read the guard as you write the claim, or write a pointer ("the spans `TestDecisionRecord` pins") instead of an enumeration that can drift.
- 2026-07-27 (M118, extends M112): an acceptance criterion that LISTS the sites to update becomes the sweep, and every site it omits ships stale. AC5 named five enumeration sites for a widened set; three fresh-context certification rounds then found five more in files it never mentioned — an operator-facing counter caption printing "less ## Review and ## Work log" above a number that already subtracted a third section, a validator comment, three docstrings, and the cap's own DEFINITIONAL line, which reverted to the two-member form with all 677 guards green. Scope such a criterion to a SEARCH over the old phrasing, never to a list of files, and expect the definitional statement of a rule to sit on a different line from the enumeration you widened.
- 2026-07-27 (M117): a mutation-registry block that is a slice BOUND the guard passes to `index()` proves nothing — blanking it raises `ValueError: substring not found`, and `guard_fails_when_blanked` returns `not wasSuccessful()`, so the crash counts as a pass (reproduced: errors=1, failures=0). A containment assert bounded by headings therefore takes guard-doctrine §2's by-hand check instead of a registry entry; register the CONTAINED phrase, never the bound. Same shape as M100's `open()` blind spot: an all-entries-green harness result can mean the engine cannot see what you think it is testing. **Extended M120:** a green §8 description-layer certification does not close this either — its three checks are AC-coverage, claim accuracy and anchor fidelity, and none of them is inversion, so M120 passed three certification rounds at zero unresolved while three asserts still survived NEGATING the rule they pin (review F1/F4/F16, scored 92/88/87). Blanking proves presence and certification proves the description is true; only guard-doctrine §1's inversion proves the assert pins the rule, and it is a separate step that must actually be run. **Extended M121:** running it once is not running it everywhere — M121 inverted its own new rules at §8 time and again at review pass 1, and pass 2's fan-out still found THREE shipped sentences that inverted green, including the section's own governing claim ("reaches one class of checking and not the other", scored 85). Each earlier sweep inverted the phrases it had just authored, never every sentence the section had gained; invert the SECTION, not your diff. **Extended M122:** the measuring INSTRUMENT drifts the same way, and green is not the only lie — a mutation script reported `RED` for a mutation that had merely CRASHED (`errors=1`, not `failures`), and a later row-drop sweep silently tested 13 of 15 rows because its regex required `## ` right after the quote, while its "exempt-only" reduction removed a hardcoded control list the table had outgrown. Both reported confidently on something other than what they named. Parse the corpus you are sweeping and derive the categories from it; read `errors` and `failures` as different words. **Extended M123:** deriving the subjects is not enough — the sweep must also report what it could not MUTATE. A registry-derived sweep found 55 §8 subjects, had a polarity substitution for only 39, and reddened 39/39; reported that way it reads as a clean section while 16 rules go unexercised. It printed them as "untested, not verified" instead, and the table was extended until every subject had a mutation (84/84 by the end). A pass rate is a lie unless its denominator is every subject, not every subject the instrument happened to handle.
- 2026-07-27 (M119): a near-miss control set proves only the wordings it enumerates, and the author picks the dodge unconsciously — the control for `^Ran \d+ tests? in ` was "Ran 3 tests **to confirm** the fix", so the shipped detector claimed "Ran 3 tests **in** isolation before the change" and `File "x.py", line 42 **is where**…", the two forms prose actually takes, until review F1 caught them. Nine §8 rounds had widened this same set. When a signature's tail is a preposition or punctuation, write the control from the sentence you would naturally write, not from a variation on the signature; and bind the signature to what machine output always emits after that point (unittest's duration, a frame's `,`-or-EOL) rather than enumerating the prose that must not match.
- 2026-07-30 (M124): a measurement script that MUTATES the file it measures must restore in a `finally:` (or verify a backup hash before reading results) — an M124 review script crashed on a TypeError between writing the mutation and restoring, every later measurement silently read the mutated file as HEAD, and the contamination surfaced only when a derivation disagreed with the committed ledger. A crash is exit-code-visible, but the residue it leaves is not (extends M56's "green is only as wide as what you ran").
