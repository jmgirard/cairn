# M339: Write hotfix flaw rows at the guest handoff

**Status:** done (2026-11-25, PR #354 https://github.com/jmgirard/cairn/pull/354)

**Goal:** A guest-mode `/hotfix` records each flaw its idea vet found in what the fix leaves as it was when it hands the PR to the maintainers, so the flaw is not lost while the PR waits for their merge.

**Outcome:** `skills/hotfix/SKILL.md` step 6 gains "Handoff flaw record": once a guest handoff's `gh pr create` succeeds (after the Copilot round when it runs), each such flaw is recorded on disk, search-first, as a new row with provenance `— added YYYY-MM-DD — hotfix PR #<n> handoff`, or as `; extended YYYY-MM-DD by hotfix PR #<n> handoff: <the flaw>` on a row that holds only its subject. A row that already holds the flaw gets no edit. A matched row, a row ending with a ` — started` token, and a records-hygiene §7 group row are never extended; the flaw gets a new row, which for a §7 group names the group row's title. A standing rejection is named in the close block, and a flaw a Copilot fix changed gets no record. Step 1's guest change route makes the same record after its push lands. Step 1's idea vet names both guest exceptions to D-225's close-block rule. Step 7's guest arm gains "Handoff flaw rows": on an accepted merged-PR re-entry it judges each Candidates row holding `hotfix PR #<N> handoff` (`<N>` the PR the argument names) against the merged diff, only the flaw inside an extended note, and deletes, narrows, or keeps it; any other outcome leaves the rows.
