## Goal

Cairn sessions add the tests the change needs, written in the host's style, and stop adding superfluous tests, test comments, model fits, and oracles.

## Scope

**In:** The rulebook's "What gets a test" floor is scoped to the change and gains exclusions. Test comments get a rule. The validation doctrine's two-oracle bar, its simulation use, and its fits are scoped to new results, and `/cairn-init`'s Conventions line follows. Guest mode matches the host maintainers' tests. The tests-first steps of implement, hotfix, and plan point to the scope rule, and the r-package and python profiles narrow their edge-case lists. The review's diff-bug reviewer gets one question about excluded tests. A decision entry and a CHANGELOG entry with copy steps record the change.

**Out:** trimming the easystats PRs, which the easystats session does, with the merged ones left as they are. A numeric review gate on test-to-code ratio or comment rate, declined at the question set. The other profiles' test-doctrine slots, which list no per-export edge cases.

## Acceptance criteria

- [x] AC1: The "What gets a test" section of `skills/shared/tracking-rules.md` scopes the test floor to the change. A new export or public function gets the full floor. Otherwise tests cover the behavior the change adds or alters. A fix gets one regression test per fixed defect, which fails on the default branch and passes with the fix. Documented and changelog claims are tested where the change adds or alters them. The section's "Never" list adds three kinds: a check repeated across inputs or classes that run the same code path, a weaker expectation after an exact one that already covers it, and a helper that does what the test framework or a snapshot already does. A test that passes on the default branch is added only to pin behavior the change could break, such as a characterization test before a refactor or a case of a shape the change leaves untouched, or where the criteria name it. It is never a guard on code the change does not touch. In guest mode, where the host's own tests do otherwise, the guest test bullet of AC4 governs.
- [x] AC2: `skills/shared/tracking-rules.md` says that a test file's comments state only what the code cannot show. They hold no narrative bug history, worked arithmetic, or oracle-type labels. A one-line citation of the published source (in guest mode the publication, not a citekey) or an issue number is allowed. A fixture's provenance lives in its committed generator or provenance fields, and its source values in its source note. In guest mode the host's comment practice governs. `skills/shared/validation-doctrine.md` no longer asks for arithmetic in comments, and it names an oracle's type in the oracle record, not in a test comment. `git grep -n "arithmetic in comments" -- skills README.md cairn/DESIGN.md` prints nothing.
- [ ] AC3: `skills/shared/validation-doctrine.md` keeps "≥2 *independent* oracle types" for a numeric result that the change adds or alters by design, and states that a fix to an existing result needs one regression test whose expected value comes from one oracle. The doctrine also states that simulation-coverage stays the primary oracle for an interval method's coverage and for an estimator with no closed form or reference implementation, and is never used to confirm a textbook property of a method the change does not add; that deterministic checks use at most one fitted model per code path, shared by the tests that use it, with a simulation-coverage oracle's replications exempt; and that in guest mode the host's practice sets the number of oracles above one, while the hard stops still bind. The Conventions line that `skills/cairn-init/SKILL.md` writes states the scoped bar. The doctrine stays under its budget of 115 lines and 8,000 bytes (`wc -l -c`).
- [x] AC4: The guest-mode bullet in tracking-rules "Collaboration mode" that matches host text to the host's own covers test files. Before it adds tests, the session reads the tests that the host's maintainers wrote, never tests from the operator's own PRs, for the code it changes, or for nearby code where none exist. It matches their number of tests per change, model fits, helper use, and comment rate. Where host practice is lighter than the floor, host practice sets the test volume, and each fixed defect keeps its one regression test.
- [x] AC5: The test steps of `skills/milestone-implement/SKILL.md` (step 4), `skills/hotfix/SKILL.md` (step 3), and `skills/milestone-plan/SKILL.md` (step 4's test-scope bullet) point to the rulebook's test-scope rule. The test-doctrine slots of `skills/shared/profiles/r-package.md` and `skills/shared/profiles/python.md` apply, to a new export and to the inputs a change touches, the edge cases that fit those inputs' types, not every listed case to every export. Each profile stays under 120 lines (`test_shipped_reference_profiles_are_valid` in `scripts/tests`).
- [x] AC6: In `skills/milestone-review/SKILL.md`, the diff-bug reviewer also reports added tests that the rulebook's test-scope, test-comment, or guest test-matching rules exclude, and step 5 settles each such finding by its ordinary rule. No numeric gate on test-to-code ratio or comment rate is added.
- [x] AC7: `CHANGELOG.md`'s Unreleased section has an entry under "Changes that affect existing repos" that states the new test-scope, test-comment, oracle, and guest test-matching rules. It tells an r-package or python repo to copy its profile's new test-doctrine lines into its own `cairn/PROFILE.md`, and a repo with numeric work to narrow the oracle line in its DESIGN.md Conventions.
