## Goal

An adopter whose Python has PyYAML gets the `cairn/**` `paths-ignore` item added to each editable `push` trigger by `/cairn-init` under one approve/decline chip, the edit verified against PyYAML's own reading before it is written and left uncommitted for the operator.

## Scope

**In:** `scripts/cairn_ci_paths.py --apply [--dry-run]` reading each workflow with PyYAML's node marks and inserting lines only, with a `safe_load` post-edit check before any write and exit 3 when PyYAML is absent; `--report` unchanged (stdlib); the §0 bullet's clause (d) rewritten around the dry run and chip; both cairn-init commit bullets excluding the edited workflow files; apply fixtures and tests, the stdlib whitelist admitting `yaml` for this script alone; a D-entry annotating D-133 and recording the optional dependency; DESIGN, CHANGELOG (M178's unreleased entry amended), tracking-rules, and prose-guard updates. Lineage: the `[high]` candidate row "Chip-applied `cairn/**` `paths-ignore` edit" (pruned at post-merge hygiene, never here); extends M178.

**Out:** rewriting a scalar `on: push` or flow-list `on: [push, …]` into block form (refused; the by-hand suggestion stands — gate choice 2026-09-06); editing `pull_request` triggers (their filter reads the whole PR diff); a `push` trigger carrying `paths` (GitHub accepts one of `paths`/`paths-ignore`; left to the operator, as M178); committing the edited workflow file (left in the working tree — gate choice); required-check handling under branch protection (the Branch-protection compatibility candidate row); switching `--report` to PyYAML (the line reader stays fixture-held to PyYAML by M178's tests).
