# M183: Close blocks say whether the next command waits on CI

**Status:** done (2026-09-10, PR #190 https://github.com/jmgirard/cairn/pull/190)

**Goal:** Every phase close on a live branch or open PR tells the user, in one plain sentence, whether the fenced next command waits on CI itself and what they do meanwhile, so "wait for green or go straight to review?" never needs guessing.

**Outcome:** The tracking-rules close-block paragraph ("Question gates and phase closes") gains a **CI line** element for a unit of work with a branch or an open PR: one plain-language sentence on whether the fenced next command waits on CI and what the user does meanwhile; a bare check state ("CI: running") never satisfies it, and it disposes of the status line's check results; restated at four named sites, every other close inheriting by citation. `/milestone-implement` step 9 states the implement-end line (nothing to wait for now, no PR yet; review pushes, opens the PR, waits at merge; on a return from review the line says review re-waits on the draft PR's checks and any shown check state is from the pre-return head). The three timeout stops — `/milestone-review` step 8, `/hotfix` step 6, `/cairn-release` step 3 — state the current check state from the wait's own source (`gh pr checks`, or the moved task's fresh output for the release check), then that rerunning the named command re-derives it and waits again, green-first optional and never required. No prose pin (D-128's precedent); D-128's wait mechanism untouched.
