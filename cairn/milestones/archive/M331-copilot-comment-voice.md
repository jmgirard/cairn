# M331: Write Copilot comments like a colleague

**Status:** done (2026-11-02, PR #346 https://github.com/jmgirard/cairn/pull/346)

**Goal:** Each Copilot review's PR comment reads as a colleague wrote it, with a draft shown first in guest rounds and in `/copilot-review`.

**Outcome:** `skills/shared/copilot-review.md` §5 now has the session write the comment in ordinary sentences, as the PR's author would write to a reviewer, with host matching governing tone and length in guest mode. The comment opens with the review's `url` as a markdown link and gives every note's outcome: a paragraph up to three notes, a list of full sentences from four. It posts with `gh pr comment --body-file` from a temp file, written before the chip, because apostrophes broke `--body`. A guest-mode round and `/copilot-review` show each draft in an `AskUserQuestion` chip with post and hold, and a typed edit posts as typed once a dropped review link is restored. A typed instruction changes the draft. A hold or a failed post resolves nothing and reports `copilot: <url> — held`, and after a hold the close fences `/copilot-review <N>` first. An owner-mode round posts with no question. The post re-reads operator comments, and threads resolve by the review tie, not by what the comment names. Each `/copilot-review` run reads `git log` first, so a note with a pushed fix gets no second fix. `/hotfix`'s guest close, `/milestone-review` step 8, README, the Unreleased CHANGELOG entries, and the hand-run guards and mutation entries follow. The module budget is under 200 lines and 12,000 bytes (193 lines and 11,513 bytes at the merge). Trigger: comments the user called "worded terribly" on easystats/datawizard; PR 738's comment is the model.
