# M193: A styled milestone band that follows the phase

**Status:** done (2026-10-01, PR #199 https://github.com/jmgirard/cairn/pull/199)

**Goal:** Redraw the milestone band so that each active milestone shows a styled header row and the next open item of its phase. That item is a task during implement and an acceptance criterion during review.

**Outcome:** `hooks/status/band.ts` builds two rows per `in-progress` or `review` milestone as styled spans. The header row has the phase label (theme `claude` for implement, `success` for review), the bold id, the title, a 10-cell bar that rounds down and is dropped below 60 `bodyColumns`, and `<checked>/<total> tasks|criteria`. The dim item row shows the section's first `[ ]` line, less its box. `no milestone file` (`warning`), `no tasks|criteria`, and `all N … checked` replace the bar, the counts, and the item row. A narrow band cuts the title before the counts. `register.tsx` draws cairn's rows in a `cairn-band` Box above the tree from `next(e)`, so another plugin's band shows beneath, and keeps the `band` atom under shape tag `band-2`. `reader.ts`, `CairnBandRow`, and `test_status_fixtures.py` carry criterion counts and `nextTask`/`nextCriterion`. The `nested-first`, `states-implement`, and `states-review` fixtures were added, for 47 mod tests. README, DESIGN, and CHANGELOG describe the two-row band. T7 checked the band live in the desktop app in both phases at normal and narrow widths.

**Decisions:** none promoted. Plan gate: a header row plus the next item over a full or expandable checklist, stacking above `next(e)` in this milestone, and no idle line between milestones (candidate row "Band idle line"). Implement gate: the phase colors and the fixed 10-cell bar.

**Review:** Three lenses plus the implement-time claim audit (69 claims, 8 corrected). Fixed at the gate: R1, the AC3 `wrap` assertion extended to the AC1 and AC2 drawings. R2, the atom shape tag, so a reload no longer draws `undefined/undefined tasks` from M191-shaped rows. R3, ragged prose wraps. R4, layout edge cases, went to the candidate row "Band layout edge cases". R5: the "Status mod follow-ons" row was narrowed at hygiene, because M193 stacks above `next(e)`. R6–R8 rejected with reasons. `claude plugin validate` does not type-check `types/index.d.ts`. One lesson added, and M105's was pruned for the cap (its rule now lives in `/milestone-review` step 5).
