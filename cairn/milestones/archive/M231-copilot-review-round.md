# M231: Hotfix and milestone PRs get a Copilot review round

**Status:** done (2026-10-10, PR #240 https://github.com/jmgirard/cairn/pull/240)

**Goal:** In a repo whose `cairn/PROFILE.md` opts in, `/hotfix` and `/milestone-review` request a Copilot review on the pull request. They then fix, reply to, and resolve each Copilot thread before the merge question, or before the close block in guest mode.

**Outcome:** `skills/shared/copilot-review.md` states the round. The opt-in line `# Copilot review: on` is also the permission for its pushes, replies, and resolves. One exit-code-first state query reads the PR's own signals: a pending request, an existing Copilot review (filtered by author), and each thread's resolved state. The round requests only on `none`, so it never requests twice and keeps no record that it ran. Owner `/milestone-review` opens the PR and requests Copilot at step 2. Step 7's PR-conversation read gives each Copilot thread its disposition, a reply (`Fixed in <sha>.`, a reason, or `Left for a follow-up.`, no thanks), and a resolve. A request still pending gets one wait of at most 10 minutes, as a Monitor over a self-exiting loop. `/hotfix` runs the round before its chip and closes the PR on a decline. Guest mode runs it after the handoff. The level is GitHub's setting (no per-request field on 2026-10-10) and is read from the review body. cairn opts in. README, CHANGELOG, the rulebook, DESIGN, and a prose guard with six mutations follow.

**Decisions:** D-152 (the PR opens before the merge question in an opted-in owner repo), D-153 (at step 2, with the read as the round; from RR17).
