# M234: Guest pushes find the fork, and intake commands work in any remote layout or shell

**Status:** done (2026-10-10, PR #243 https://github.com/jmgirard/cairn/pull/243)

**Goal:** Close five issue-intake and guest-mode edges from the M232 and M233 reviews, so that cairn's commands reach the right remote and repo in any shell or locale.

**Outcome:** The rulebook's canonical recipe defines the guest fork remote `<fork>`: the one remote other than `<base>` whose `gh repo view --json parent` parent equals `<base-repo>`. A non-fork prints `/`, and a failed read is not a match. With no match or more than one, a guest push stops and names the remotes, parents, and failed reads. `<fork-owner>` reads `<fork>`. Every guest push in `/hotfix`, `/milestone-review`, `/milestone-implement`, `/milestone` §2, `copilot-review.md`, and the rulebook names `<fork>` (11 sites). `/milestone` §2 opens with a "The repo." rule, and its 15 `gh pr`/`gh issue` commands carry `--repo <base-repo>`. `gh pr checks` takes the header PR number or the branch. The rulebook's Intake paragraph names `close` for an orphaned issue, and the `leave` clause is unchanged. §4's reply hand-off writes the draft to `cairn-reply-<owner>-<repo>-<N>.md` in `tempfile.gettempdir()` (Read it first if it exists) and hands over `gh issue comment --body-file`. The `'\''` rule and the four-backtick fence are gone. The rulebook-mass line uses `wc -l -c`, re-seeded to 636 lines / 60,714 bytes at its three sites. New guards: `test_guest_fork_remote.py` and `test_milestone_gh_repo.py`, plus additions to `test_issue_look_in.py` and `test_issue_triage.py`, with one mutation entry. CHANGELOG and README follow.
