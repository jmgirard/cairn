# M284: A candidate row that waits on its trigger is parked, and the pane shows it last with an hourglass

**Status:** done (2026-10-18, PR #296 https://github.com/jmgirard/cairn/pull/296)

**Goal:** A candidate row whose promotion condition has not held opens with a `[parked]` token that the skills write and remove, and the cairn pane draws such rows last, each with a gray `⧗`.

**Outcome:** tracking-rules "Candidate priority token" defines `[parked]` as a fourth opening token, in place of `[high]` or `[low]`. Whoever adds a row writes it when the row's condition does not hold, and the order is high → normal → low → parked. "Candidate short title" removes `[parked] `, and the `/cairn-init` skeleton shows a parked row. `reader.ts` and `cairn_next.candidate_texts` read exactly `[parked] ` as `parked`, `types/index.d.ts` gains the value, and `high_title`/`nextTitle` still pick only `[high]` rows. `cairn_validate`'s `candidate order` ranks `parked` lowest. The pane's `PRIORITY_MARK.parked` is a gray `⧗` with a gray title, and `LEVEL_RANK` draws the parked rows last. The new fixture `candidates-parked` holds the probe rows. `/cairn-triage` re-rates a row to and from `parked` on a `keep`, `compress`, or `retitle` row, never re-parks a `[high]` row, and a promote writes `[high]`. `/milestone-review` step 9 unparks a row that the milestone file quotes or that names the milestone, where the merge made the condition hold. README, DESIGN.md, and a CHANGELOG Unreleased entry describe it. This repo's 24 candidate rows are parked, and 13 of them gave up `[low]`.

**Decisions:** D-184. The question set chose an explicit token that the skills write over detecting "promote" in row prose, and a gray hourglass in the mark position with the parked rows as their own group below `[low]`. Named `[parked]` because the pane already has a Waiting section. Criteria audits (full): 11 findings on the prose-detection draft, then 10 on the token design, all fixed.
