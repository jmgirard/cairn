# M191: Milestone status band, a Claude Code mod inside the cairn plugin

**Status:** done (2026-10-01, PR #198 https://github.com/jmgirard/cairn/pull/198)

**Goal:** Ship a Claude Code mod inside the cairn plugin that draws the active milestone, its phase, and its task progress above the prompt.

**Outcome:** `hooks/status/register.tsx`, named under a new `modules` key in `hooks/hooks.json` beside the unchanged `hooks` key, draws one `AbovePrompt` line per `in-progress` or `review` ROADMAP row: id, title, phase, and checked/total `## Tasks` boxes, or `no milestone file`. It refreshes at `session.start` and each main-loop `turn.complete`, and passes to the engine with no root or no active row, or during a survey. `reader.ts` mirrors `parse_roadmap_rows_full`, `_section_body`, `_AC_ITEM` and `find_cairn_root`, and reads a milestone path only when it is a regular file. `types/index.d.ts` is the `cairn.band` state contract. Seven fixtures under `hooks/status/fixtures/` feed `gen_fixtures.py` → `fixtures.gen.ts`, which 33 `claude plugin test` cases on terminal and desktop read. `scripts/tests/test_status_fixtures.py` holds the Python helpers to the same fixtures and fails on a stale module. The verify slot gates `claude plugin validate` and `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude plugin test .` (the rollout switch can serve hooks modules off to a process). README, CHANGELOG, DESIGN and CLAUDE.md describe the band and its gates.

**Decisions:** D-143 (plan). Kept the TypeScript reader after its falsifier fired (`$.plugin.root` exists), because a test cannot fake `$.process.run` either and python3 would run at every turn end. AC1–AC3's "Shown by" wording was amended at a gate on a false spike finding, then reverted to the plan text, AC1 keeping one live desktop look.

**Review:** Three lenses, 28 findings. Fixed at the gate: a FIFO or device path stalls a read, so the reader now checks `isFile` first, DESIGN/CLAUDE.md/PROFILE named only the Python gates, and a README paragraph had moved under the band heading. Two went to the "Status mod follow-ons" row: the band hides other plugins' `AbovePrompt` bands, and a Windows UNC walk passes the share root. The other 20 were rejected with reasons. Live: the band showed in the desktop app and followed edits (3/6 → 4/6 → 5/6), the guard denied a merge in a fresh session that got the tracking context, and on 2.1.284 headless the guards and context worked while the module did not load.
