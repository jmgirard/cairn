# M332: Write host text so a maintainer follows it

**Status:** done (2026-11-02, PR #347 https://github.com/jmgirard/cairn/pull/347)

**Goal:** Text a session writes for another person reads clearly on one read, because the rules ask for that and stop prescribing a shape for it.

**Outcome:** The guest host-text bullet in `skills/shared/tracking-rules.md` and the session-start text in `hooks/session_context.py` now have the session check, before it commits, shows, or posts such text, that a maintainer who has not seen the session can tell on one read what it says and anything it asks. The check comes before matching length, tone, and level of detail, and text that fails is rewritten. `skills/shared/copilot-review.md` §5 applies the same test in every mode. The comment keeps ordinary sentences and carries the review's URL as a markdown link at no set place. It names each fix and any other note a PR reader could ask about, and one sentence is enough when none needs naming. The fixed opening, the outcome for every note, the paragraph-or-list rule, and the example comment are gone. `/copilot-review`, README, and CHANGELOG follow. `/milestone-plan`'s maintainer question no longer lists points. `/milestone-review` step 8 and `/hotfix` say a guest PR body is short unless that costs clarity. The rulebook baseline is 894 lines / 88,662 bytes. Trigger: the user called about a dozen easystats drafts on 2026-11-02 badly worded. In the same turn, outside this repo, the user's `SIMPLE_ENGLISH_LINT_EXCLUDE` setting gained `*/scratchpad/*`, `*/cairn-question-*`, and `*/cairn-copilot-comment-*`.

**Decisions:** D-236 (the clarity check and its order, the comment with no set shape; supersedes D-235's opening and every-note clauses; narrows D-187, D-212, and D-207's short body; annotates D-207's order).
