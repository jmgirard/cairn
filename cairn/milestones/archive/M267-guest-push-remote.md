# M267: Let a guest repo push its branches to the maintainers' repo

**Status:** done (2026-10-16, PR #279 https://github.com/jmgirard/cairn/pull/279)

**Goal:** In guest mode, a repo whose `cairn/PROFILE.md` asks for it pushes its milestone and hotfix branches to the base repo instead of the fork, after the skill checks that the operator's account can push there.

**Outcome:** tracking-rules' git model gains the push remote `<push>` (`<base>` under the header line `# Push remote: base`, else `<fork>`; owner mode never reads it; no validator does) and `<push-owner>`, and the open-PR head rule: a branch with an open PR is pushed to `<head-remote>`, found from `headRepositoryOwner.login` (`<base>` or `<fork>`, ignoring case; any other owner or a failed read stops). The fork-remote stop applies only to pushes that resolve to the fork. `/milestone-review` step 8's guest handoff and `/hotfix`'s guest handoff run `gh api repos/<base-repo> --jq .permissions.push` before a push when `<push>` is `<base>` and stop with nothing pushed on any answer but `true`; step 8 skips `gh pr create` when the header names an open PR. `/milestone-implement` step 2's guest sync finds a pushed branch with `git ls-remote --exit-code --heads` on the head remote else `<push>`, reads `git rev-list <slug>..<remote>/<slug>` before the rebase, stops on output, else rebases and pushes with `--force-with-lease=<slug>:<sha>`; review step 1 takes that sync whole. `/hotfix`'s change route, `/milestone` §2, and copilot-review's fix pushes point at the head rule. README guest bullet, CHANGELOG entry, `test_guest_fork_remote.py` rewritten (16 tests), `test_resume_routing.py` and one mutation block updated.

**Decisions:** D-172 (annotates D-137 and D-171). Plan gate: a PROFILE.md header over an automatic push-permission check; a stop on remote-only commits over pulling them in. Implement: the change route resolves its head remote from the PR's head owner, not the upstream `gh pr checkout` sets.
