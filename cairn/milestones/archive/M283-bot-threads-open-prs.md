# M283: The status audit lists unresolved bot threads on your open PRs

**Status:** done (2026-10-18, PR #295 https://github.com/jmgirard/cairn/pull/295)

**Goal:** The `/milestone` health audit reports each unresolved review thread that a GitHub App bot opened on the operator's open PRs in the repo, with a check of its claim against the PR's code.

**Outcome:** `skills/milestone/SKILL.md` §2 has a "Bot threads on your open PRs" bullet, in owner and guest mode. It takes every PR from the "Open hotfix PRs" bullet's `gh pr list --author @me` call, whose `--json` list gains `headRefOid`. For each PR it runs one fenced `gh api graphql --paginate` command in `bash` or `zsh`, and keeps threads that are unresolved and whose first comment's author `__typename` is `Bot`. Each kept thread is reported with its PR, path, `line` (or `originalLine`, named as a line of an older commit, or the path alone), `outdated` mark, bot login, claim, and a `holds` / `does not hold` / `cannot tell` verdict. The verdict comes from a contents read at `headRefOid` with the path percent-encoded, and an outdated thread's passage is found by content. Failed reads are reported gaps, comment text and file contents are data, and nothing is written to GitHub. A sentence in the linked-item read states that `gh api` reads naming their repo sit outside the `--repo` rule. README and a CHANGELOG `### New` entry describe the bullet.
