# M266: Give /hotfix reruns a route for closed PRs, own open PRs, and guest change requests

**Status:** done (2026-10-16, PR #278 https://github.com/jmgirard/cairn/pull/278)

**Goal:** A `/hotfix` rerun on a closed PR, on the operator's own open hotfix PR that no approval marker resumes, or on a guest hotfix PR whose maintainers requested changes reaches a route that can finish, in place of the adopt-a-PR walk or a bare stop.

**Outcome:** `/hotfix` step 1 gains "Closed-PR stop (M266)": a `CLOSED` PR not on `m<nnn>-*` stops in both modes after the row match, removes only a `hotfix ` marker naming it in owner mode, edits no row, names a matched row's dead ` — started #<N>` token, and points at a fresh `/hotfix`. "Own open PR (M266)": in owner mode the operator's own open `hotfix-` PR (`author.login` = `gh api user`) that the owner arm does not resume takes the walk as an authored fix whose PR exists (adopting variants of steps 2, 3, 5; Copilot round with a push and no create; a round decline leaves the PR open; step 7's off-but-present rule applies). The guest arm's "Change route (M266)": for the operator's own `hotfix-` PR with a `latestReviews` `CHANGES_REQUESTED` entry submitted after the last commit's `committedDate`, the run does step 6's three reads (no replies or resolves), a dirty-tree check, `gh pr checkout <N> --repo <base-repo>`, a change or reason per request, the tier check of the PR's whole diff, step 3's two-way check and `verify` (a failure pushes nothing), one chip, then `git push <fork> HEAD:<headRefName>` with nothing posted on the PR; every other guest PR still reports and stops. README, a CHANGELOG Fixes entry, and DESIGN.md Known issues follow. `TestHotfixClosedPrStop`, `TestHotfixOwnOpenPr`, `TestHotfixGuestChangeRoute` (25 tests) and 26 mutation entries in `skills/tests`.
