# M268: Let a guest milestone build on one that waits for the maintainers

**Status:** done (2026-10-16, PR #280 https://github.com/jmgirard/cairn/pull/280)

**Goal:** In a guest repo that pushes to the base repo, a milestone can depend on a handed-off milestone, with its branch and PR built on that milestone's branch until the first PR merges.

**Outcome:** A stack base is, in guest mode under `# Push remote: base`, a `blocked` dependency whose milestone header names a PR URL (an archived one counts as `done`). `cairn_next.workable` and `waiting` (`stack_bases`, `_met`) and the pane reader (`unmetDeps`, `pushRemote`) count a `planned` milestone workable when each dependency is `done` or a stack base and at most one is a stack base; `cairn_common.push_remote` reads the line through a shared header reader that skips a non-regular PROFILE.md. Six fixtures (`stack-base`, `stack-owner`, `stack-no-push-line`, `stack-no-pr`, `stack-in-progress`, `stack-two-bases`) hold both readers. `/milestone-implement` step 1 stops on two or more stack bases, a base PR URL outside `<base-repo>`, a base PR not `OPEN`, a chained base (`baseRefName` not the default branch), a fork-headed base PR, and a branch `git ls-remote <base>` does not list; step 2 cuts from `<base>/<stack-base-branch>`, and its stacked sync replaces the plain guest rebase: `git rebase --onto <base>/<stack-base-branch> <old> <slug>` while the base PR is open, the restack `--onto <base>/<default-branch>` once it merged, the lease push only for a pushed branch, `gh pr edit --base <default-branch>` only when `baseRefName` still names the base branch, a `stack base: <branch> at <sha>` work-log line written last, then `verify`. Review step 1 syncs a stacked branch only while its base is open; step 8 adds `--base` and a body line naming the base PR, routes a merged base to implement with a `restack:` line, and stops on a closed one. `/milestone` §2 routes the restack and reports a closed base. tracking-rules' Collaboration-mode bullet defines stack base, stacked milestone, the post-hygiene lookup by `headRefName`, and the restack; every workable-rule site, README guest bullet, and CHANGELOG carry it.
