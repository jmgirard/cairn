# M297: A trivial edit closes the issue of the row it deletes

**Status:** done (2026-10-20, PR #310 https://github.com/jmgirard/cairn/pull/310)

**Goal:** In owner mode, when the trivial route deletes a candidate row whose short title ends with an issue number, the route closes that issue after its push, and the tier chip's option names the close before the user chooses.

**Outcome:** `/milestone-plan` step 1 gains an **Issue read (trivial route, owner mode)** paragraph: for each deleted row whose short title ends with `(#N)` or `(#N, #M)`, the plan runs `gh issue view <N> --repo <base-repo> --json state,url` before the chip (no issue body). The route closes a number that reads `OPEN`, whose URL path holds `/issues/`, and that no kept row's title reference holds (a kept row: one the edit narrows or leaves in place). It leaves alone a closed number, a `/pull/` number (`gh issue view` reads PRs too), an unreadable one, and a kept row's. The trivial option names each number to close and each left alone with its reason, and says the commit summary ends with the deleted rows' references. After a successful commit and push the route runs `gh issue close <N> --repo <base-repo>` per named number and re-reads it, and the close block names each closed or left open. A failed commit or push closes nothing, and a failed push's block gives the close command for later. A narrowed row's issue stays open; guest mode reads and closes nothing. The rulebook's trivial-tier sentence names the close. `skills/tests/test_plan_tier_check.py` pins the sentences, the option-scoped ones within the option text; README's trivial-edit row and an Unreleased "Changes that affect existing repos" entry state it.
