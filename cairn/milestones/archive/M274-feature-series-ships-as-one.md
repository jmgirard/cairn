# M274: A feature split across milestones reaches users as one change

**Status:** done (2026-10-18, PR #286 https://github.com/jmgirard/cairn/pull/286)

**Goal:** When a plan splits one user-facing feature or fix across several milestones, the feature reaches users, and the changelog, as one change.

**Outcome:** tracking-rules "Sizing and the work tiers" gains a "Feature series" paragraph: two or more milestones one plan splits from one feature or fix; (a) earlier parts keep new behavior out of users' reach where they can (an internal layer, not a vertical slice); (b) each earlier part's `Out:` item names the last as where exports, docs, and (unless (c)) the changelog entry land; (c) an earlier part that must change visible behavior owns the one entry and later parts edit it; (d) guest stacking limits (one open earlier part with `# Push remote: base`, none without). The plan writes a `feature series: M<a> -> M<b>[ -> …]` work-log line in each part. `/milestone-plan` step 4 bullet (every part a milestone file). The python, r-package, claude-plugin, and docker-image profiles' changelog gate accepts an edit to the series' existing entry and no entry for a hidden earlier part; this repo's `cairn/PROFILE.md` copy too, and the CHANGELOG tells existing repos to copy the sentences. `/milestone-review` step 8 guest arm: one plain PR-body sentence on whether the PR completes the series, the last naming earlier PRs from live headers or archive Status lines. `/cairn-release` step 1 lists half-merged series from live milestone files and gives each unfinished part's ROADMAP status. Guards: `skills/tests/test_feature_series.py` with mutation entries; README tip; rulebook-mass baseline re-seeded to 733 lines / 70,960 bytes.

**Decisions:** none promoted. Question set: owner-mode release warning yes; hiding earlier parts is "prefer, with fallback". The plan gate chose an `Out:` item plus a work-log line over a new header slot, and prose rules over a validator.
