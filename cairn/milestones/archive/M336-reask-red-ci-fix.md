**Status:** done (2026-11-05, PR #351 https://github.com/jmgirard/cairn/pull/351)

**Goal:** In owner mode, `/milestone-review` merges a red-CI fix only after the user approves the merge again, whatever the fix's size.

**Outcome:** `skills/milestone-review/SKILL.md` step 8 gains the **Red CI** paragraph. A failed check found by the first read, a wake, or a `gh pr checks` read after a failed `gh pr merge` takes it. The session removes `cairn/.merge-approved`, commits the fix, re-verifies, leaves it unpushed, runs step 7's PR-conversation read, blocking rule, and changed-snapshot list, and re-poses the merge chip with the failed check and what the fix changed. On approval a new `step-7 approval:` line is committed and step 8 runs again from the push. A rejected push stops, and a fix-now push on a Copilot-arm PR can carry the fix first. The companion arm does the same before that companion merges, with a re-entry check for commits past its PR head. The no-checks re-read in step 8 and `/hotfix` step 6 covers a PR pushed moments ago. README and CHANGELOG say so. DESIGN's Known issue "A typed resume can restart CI" gains route (c)'s push of an unasked fix. The hook's "without re-asking" note stays.
