# M320: Keep lessons in fixed ranked slots

**Status:** done (2026-10-24, PR #333 https://github.com/jmgirard/cairn/pull/333)

**Goal:** `cairn/LESSONS.md` keeps a fixed number of short lessons, and a new lesson replaces the one whose last use is oldest.

**Outcome:** The rulebook's Weight caps replace the `LESSONS.md` 20,000-byte budget with at most 25 lessons, each one line of at most 450 bytes (the 50-line cap stays as the validator backstop), and define a lesson's rank as the highest milestone id in its provenance, ids after `trimmed` or `corrected` excepted. `/milestone-plan` writes a `lessons used:` work-log line in each milestone file. `/milestone-review` hygiene marks those lessons and each lesson whose trap the milestone met `used M<NNN>`, sends an over-450-byte extension to its own lesson, and at 25 lessons evicts the lowest-ranked unpinned, unquoted lessons (none when too few can go; quoted in full in guest mode). `/cairn-triage lessons` gains `split`, a length rule (every lesson over 450 bytes is compressed or split, a pinned string kept whole), and a `rank` drop exit down to 20 lessons; "prune the stalest" and the keep-with-reasons option are gone. The `/milestone` audit, the lessons template, the cairn-init tree comment, README, and a CHANGELOG entry follow. This repo's file went from 32 lessons (19,993 bytes) to 20 (three long lessons split, seven compressed, 20 rank-dropped; the work log lists each).
