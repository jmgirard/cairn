# M330: Ask who wanted the work in guest plans

**Status:** done (2026-11-02, PR #344 https://github.com/jmgirard/cairn/pull/344)

**Goal:** In guest mode, a plan asks whether to do work that nobody outside it asked for, before any file is written for that work.

**Outcome:** Guest `/milestone-plan` step 2 gains an "Outside demand" paragraph. Fixes for a wrong number, a crash, or broken documented behavior are outside it. For other work the plan runs the maintainer decision's read, needed or not, and reads each issue or PR any repo's request or row cites, a PR's body included. Someone asked when another person asks for the change, reports a problem it fixes that still occurs at the base head, or a maintainer agrees. A text by the operator or a bot does not count, nor does a link to an issue that does none of these. When no one asked and the maintainer question covers the work, that question says so and no separate question is posed. Otherwise it is a flaw, recorded in the `idea vet:` line, with build anyway, someone already asked, and do not build, the last recommended. If the plan can say what goes wrong for a user, a draft issue comes first and is recommended, reusing the maintainer question's temp file, command, rerun, and wait option, with a parked row saying `promote when someone asks for it`. A place no read can reach goes on as the user named it, and a maintainer's no at a named place stops the plan. Step 7's close list and the rulebook's question-set sentence name the question, and the rulebook seed is 892 lines / 88,366 bytes. README and CHANGELOG state it. No new header slot, work-log line, or validator failure.
