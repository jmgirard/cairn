# M313: Scope the tests cairn sessions add

**Status:** done (2026-10-22, PR #326 https://github.com/jmgirard/cairn/pull/326)

**Goal:** Cairn sessions add the tests the change needs, written in the host's style, and stop adding superfluous tests, test comments, model fits, and oracles.

**Outcome:** The "What gets a test" floor in `skills/shared/tracking-rules.md` now covers the change. A new export, or a branch a change adds to an existing one, gets the full floor. Otherwise tests cover the behavior the change adds or alters, with one regression test per fixed defect. A test that passes on the default branch needs a reason: it pins behavior the change could break, tests a documented claim the change adds, or the criteria name it. It is never a guard on untouched code. The "Never" list gains repeated same-path checks, weaker expectations after an exact one, and duplicate helpers. A new "Test comments" paragraph bars narrative history, worked arithmetic, and oracle labels, and allows citations, issue numbers, and the profile's provenance shapes. A guest bullet, "Tests added to host code match the host's tests", reads the maintainers' tests with `git blame` and matches their volume, fits, helpers, and comments. Failure identity and check discrimination still bind. `skills/shared/validation-doctrine.md` gains a Scope paragraph: the two-type bar covers results added or altered by design, a fix needs one oracle, and deterministic checks share one fit per code path, with simulation replications exempt. Simulation is never used for a textbook property of an untouched method. The implement, hotfix, plan, and cairn-init sites point to the rules. The r-package, python, and generic profiles are scoped. The review's diff-bug lens gains question (c). The CHANGELOG gives copy steps, and the `/milestone` rulebook-mass baseline was re-seeded to 792 lines / 76,924 bytes. Trigger: an easystats audit of 60 cairn PRs.
