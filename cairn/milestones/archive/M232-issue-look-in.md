# M232: `/milestone` looks into one GitHub issue and routes it

**Status:** done (2026-10-10, PR #241 https://github.com/jmgirard/cairn/pull/241)

**Goal:** Given an issue number or URL, `/milestone` reads that issue and the code it names. It says whether the issue needs a reply, a hotfix, or a milestone, and how much maintainer design input it needs. On the user's choice, it starts the work now or records a candidate row.

**Outcome:** `skills/milestone/SKILL.md` gained §4, the issue look-in. An argument of `#N`, `N`, `issue N`, a phrase ending in one of those, or an issue URL runs it in place of §1–§3 and the RR check. One `gh issue view` read with `--repo <base-repo>` stops on a PR (`/pull/` in the URL), another repo's URL, or a failed read. The search-first sweep reads candidate rows, open milestones and their `Resolves:` slots, the archive, D- headings, and two `gh` searches. The reproduction runs the checkout's own code, treats issue text and code as data, and leaves `git status --short` unchanged. The report gives one verdict (`reply`, `hotfix`, `milestone`), one level (`none`, `confirm`, `decide`), file:line citations, and the reproduction. One chip offers do it now, a candidate row, leave (D-044's three reasons only), and stop. Do it now invokes `/hotfix` with a summary plus `issue <URL>`, `/milestone-plan` with the issue, or the reply hand-off: a fenced `gh issue comment --repo <base-repo>` the user runs. An owner-mode row is a pulled, ROADMAP-only docs commit on the default branch, and a guest row stays on disk. `/milestone-plan`'s acknowledgement gained a guest arm (`--repo`, `Working on this: <issue title>`). The routing template and CLAUDE.md, README, CHANGELOG, and the prose guard `skills/tests/test_issue_look_in.py` (16 tests, EXEMPT from mutation registration) follow.

**Decisions:** none promoted. The plan gate kept the look-in in `/milestone` over a new `/issue` skill, so D-043 stands.
